# 场景：工厂在线 / 设备 PdM 监测

> Tinia Production 的目标场景（2027 路线）。**当前不卖**，但要给客户讲清楚"未来一年我们怎么演进到这里"，避免客户在 2026 选择竞品做在线监测。

---

## 客户画像

- **类型**：
  - 风电场远程运维方
  - 工业泵 / 电机厂 PdM 团队
  - 燃气轮机 / 大型旋转机械维保团队
  - 制造业产线设备健康监测
- **业务**：传感器实时采集 → 异常检测 → 提前预警 → 减少停机
- **当前工具**：
  - 大多是"传统震动监测 + 简单阈值告警"
  - 一些用 GE Bently Nevada / NI LabView 等
  - 部分自建 Python 在线系统但功能简单

---

## 痛点 vs Tinia Production 解法

| 痛点 | 现有工具 | Tinia Production（2027）|
|---|---|---|
| 算法太简单（仅阈值告警）| ✅ 跑得动但不智能 | DAG + 心声 + ML 复杂指标 |
| 想加新算法很难 | 厂家定制 / 自己写 | 节点商店订阅 / AI 自研 |
| 多机协同难 | 各机器各自跑 | 一条产线统一调度 |
| 跟 MES / ERP 集成困难 | 各厂家专有接口 | 标准 REST API |
| 模型 / 算法升级麻烦 | 升级要现场重装 | OTA 远程热更新 |
| 工程师不会用 | 学习曲线陡 | AI 工程师助手降低门槛 |

### 关键能力（区别于 Tinia Pro）

| 能力 | 说明 |
|---|---|
| **实时流处理** | 秒级延迟 vs Pro 离线批处理 |
| **多机协同** | 一条产线 5-20 个工位同时跑同一流程定义 |
| **数据库 / MES 集成** | 分析结果直接进 ERP / MES |
| **告警 + 推送** | 异常超阈值实时邮件 / 短信 / Webhook |
| **模型 OTA** | 云端改流程 → 自动推到边缘节点热更新 |
| **离线 / 在线同源** | 同一份流程定义，离线分析跟在线流处理用同一份 |

### 跟 Tinia Pro 的关系

- **架构上**：tinia-engine 跟 tinia-runtime 的分离就是为 Production 准备的
- **流程定义**：相同 JSON Schema，离线 / 在线无缝切换
- **节点生态**：相同节点市场，Pro 节点 + 流处理节点
- **客户路径**：Pro 客户可以零迁移升级到 Production
- **学习曲线**：Pro 用户上手 Production 几乎无新学习成本

## 当前 / 过渡方案（2026）

### 客户现在想做在线监测怎么办？

#### 方案 A：用 SmartQuality（Bestfunc 现有产品）

- SmartQuality 是 Bestfunc 已有的工业声学在线检测产品线
- 现在已在汽车 NG 检测 / 产线声学一致性等场景上跑
- 客户当前需求大多能满足

#### 方案 B：Pro 桌面版 + 离线分析支撑

- 用 Tinia Pro 桌面版做离线分析、训练模型、调参
- 调好的流程导出给现有在线工具用（或者临时拿 Pro 跑批处理）

#### 方案 C：等 2027 Production v1.0

- 跟客户提前打招呼："我们 2027 出在线版本，您先用 Pro 把离线流程跑通，到时无缝升级"
- 适合愿意等的、希望长期跟 Tinia 绑定的客户

## 销售场景

### 客户："我们想做风电场在线 CMS"

**1. 不要 oversell Tinia Production 已经能做**

诚实说："Tinia Production 在产品路线图上，2027 正式推出。如果您 12-18 个月内启动 PoC，正好赶上首批客户。

当前我们能提供：

- 离线分析：用 Tinia Pro 把您历史数据跑通，验证算法 + 训练异常检测模型
- 在线检测：可以先用 SmartQuality（Bestfunc 现有产品）过渡，2027 升级到 Production
- PoC 阶段：我们派人现场支持，跟您一起设计部署架构"

**2. 给具体路径**

```
2026 H2：Tinia Pro 离线跑通您的算法 + 出 PoC 报告
2027 Q1：Tinia Production 设计 → PoC 选型 → 您是首批用户
2027 H2：现场部署 + 测试
2028：全产线上线 + 长期维护
```

**3. 商业模型**

- 离线分析阶段：Pro 多 seat
- PoC 阶段：项目咨询费 + 集成开发
- 上线阶段：Production 项目交付（含硬件 / 集成 / 运维）

### 客户："我们工业泵 PdM 想升级"

类似路径：

- 2026：用 Tinia Pro 做离线诊断 + 模型训练
- 2027：Production 上线部署到设备现场

## Production 客户的关键差异

跟 Pro 客户对比，Production 客户有几个特殊点：

| 维度 | Pro 客户 | Production 客户 |
|---|---|---|
| 决策周期 | 几周到几个月 | 半年到一年 |
| 决策人 | 工程师 / 主管 | 工厂老板 / 设备总监 |
| 关键关注 | 工程师效率 | 产线 OEE / 故障预防 ROI |
| 部署 | 工程师 PC | 工厂 IT + 边缘硬件 |
| 服务 | 主要技术支持 | 长期运维 + 模型迭代 |
| 商业 | seat 订阅 | 项目交付 + 服务费 |
| 客户成功 | 月度跟进 | 周度甚至日度跟进（关键阶段） |

## 风险与缓解（销售要心里有数）

| 风险 | 影响 | 缓解 |
|---|---|---|
| 2027 Production 延期 | 客户失望 | 销售时给"路线图"而不是"承诺"，过渡方案打底 |
| 客户嫌等不及选竞品 | 流失 | 给离线 Pro 先合作建立关系 + 显示技术深度 |
| 客户算力 / 网络条件不够 | 部署失败 | PoC 阶段先验证基础设施 |
| 模型精度不达标 | 客户不付尾款 | 离线阶段先证明算法可行性，不冒进上线 |

## 长期愿景（讲给内部听）

- 2027 Production v1.0 上线 → 5-10 个首批客户
- 2028 行业模型库累积 → 10-30 个长期客户
- 2029+ 行业默认 PdM 工具之一 → 跟 GE / B&K 同台竞争

Tinia Production 是 SmartQuality 已经走通路径的复用 + Tinia 节点生态的下游变现 + AI agent 的工业落地场景。
