# 场景：整车厂 NVH 工程师的典型工作流

> 给销售 demo / PM 设计功能 / 新员工理解客户用。完整描述一位整车厂 NVH 工程师一周的工作 + Tinia 怎么帮。

---

## 客户画像

- **公司**：某新能源车企 NVH 部门
- **岗位**：电驱 NVH 工程师，工作 5 年
- **当前工具**：HEAD ArtemiS（公司买的，共用 license，要排队）+ MATLAB（自己写）
- **痛点速览**：
  - HEAD 排队等不到，老用 MATLAB 凑合
  - 写 MATLAB 代码每次都要从老项目复制粘贴改
  - 每周给老板出周报 1-2 小时手工搭流程
  - 跟测试中心传数据靠百度网盘
  - 想试新算法（论文里的）→ HEAD 没有，自己写又懒

## 一周典型工作（用 Tinia）

### 周一上午：例行数据分析

**任务**：测试中心刚送来一台新样车在转鼓上的电驱 NVH 数据（约 2GB wav + RPM CSV），出基础 NVH 报告。

**用 Tinia**：

1. 打开 Tinia 桌面版，进数据源页
2. 把 wav + CSV 拖进数据源（Tinia 自动识别 + 创建 Composite DataSource，按文件名匹配麦克风 + RPM 通道）
3. 打开"电驱 NVH 标准流程"模板（上次保存的）
4. 替换数据源 → 一键运行
5. 流程跑完（约 5 分钟）：
   - Order Tracking 出 Campbell 图
   - 主要阶次（10×、12×、24× 等）的趋势
   - 心声指标（loudness / sharpness）vs RPM
   - 异常段自动标记
6. 在看板（Dashboard）编辑器里拖几张图组成"今天的报告"——看板支持流式拖拽 / 自由布局、整屏排版（所有组件缩到一屏直接拖动重排）、视图 + 章节标题 + 文本（富文本 + 插图）+ 图片 / 多图 + HTML + 视频等多种组件，多选同类组件还能批量改属性
7. 看板「分享」生成链接发给老板——内容走快照固化，链接长期可访问（不随运行记录清理失效）；PDF / Word / PPT 模板导出在路线图上

**时间**：约 30 分钟（之前用 HEAD + MATLAB 要 2-3 小时）

---

### 周一下午：跟同事讨论某个异常

**任务**：周一报告里发现某 RPM 段心声 sharpness 异常高，叫上同事一起看。

**用 Tinia**：

1. 同事在自己机器上打开 Tinia
2. 你把流程 share 给同事（流程 JSON + 数据源链接 + GraphRun ID）
3. 同事在自己的 Tinia 里打开 → 看到完全一致的可视化
4. 在 Viewer 里同事用 slicer 把时间轴拖到异常段
5. 同事说"这个看起来是齿轮啸叫" → 你跟 Claude Code 说"帮我找一个齿轮啸叫识别的节点"
6. Claude Code 在商店里搜 → 找到一个高校研究者发布的"齿轮啸叫识别"节点
7. 你订阅 + 加到流程
8. 重新跑 → 验证假设

**时间**：协作 + 加新算法 + 验证 1 小时（之前要"等 HEAD 下个版本支持齿轮啸叫"几个月）

---

### 周二：写定制分析节点

**任务**：领导要求做一个"电驱效率 vs 噪声"专题分析，公司内部没有现成工具。

**用 Tinia + Claude Code**：

1. 在 VSCode 打开 Claude Code，跟它说：
   > "我想做一个节点，输入电驱效率（CSV 时间序列）+ 噪声音频，输出'效率 vs 噪声'的散点图 + 相关性指标"

2. Claude Code 调用 MCP 工具：
   - `dev_create_project` 新建项目 `acoustic-tools`
   - `dev_create_node` scaffold 节点 `efficiency_vs_noise`
   - 读官方 `indicator_viewer` 节点的代码学风格
   - 写 `run.py`（pandas 读 CSV + numpy 算相关性）
   - 写 `ParamsForm.tsx`（参数：时间窗口、相关性方法）
   - 写 `Viewer.tsx`（散点图 + 相关性 R 值显示）
   - `dev_reload` 让 Tinia 装载

3. 你说"测一下"，Claude Code：
   - `flow_create` 建测试流程
   - 接你之前的电驱数据
   - `flow_run` 跑通 → 看 outputs

4. 你看 Viewer 觉得"R 值显示不够明显"，跟 Claude Code 说"R 值大字显示"，它改 Viewer.tsx → reload → 重新看

**时间**：从零到能用约 2-3 小时（之前用 MATLAB 写 + 调 + 出图大概 1-2 天）

> 💡 另一条路：如果工程师手里已有一堆 Python 脚本不想全搬进平台，可以让超管在「SDK 管理」生成一个 SDK 包（凭据 + 地址已内置），在自己脚本里 `import tinia_sdk`，把"算响度 / 跑倍频程"这类已在平台调好的分析当函数调用——传文件路径或数组进去、拿结果出来，算法仍在平台执行、参数在平台改了自动生效。

---

### 周三：发布节点 / 分享给同事

**任务**：周二写的 `efficiency_vs_noise` 节点其他同事也想用。

**两种选择**：

**A. 私有发布到公司组织池**：

1. `pack-and-publish` skill → `dev_bump_version` → `dev_export`
2. `publish-plugin` skill → `plugin_publish_submit`，scope="org_only"
3. 公司 admin 审批通过 → 公司内所有 Org member 都可订阅装上

**B. 公开发布到商店**（如果不涉密）：

1. 同上发布，scope="public"
2. 商店运营审批通过
3. 全行业可订阅，你可能因此收到几个免费下载 + 几条评分

**时间**：公司内分享 10 分钟（之前要拷代码 + 写文档 + 群里讲解 1 小时）

---

### 周四：跟测试中心远程调试

**任务**：测试中心做某个工况测试时遇到数据"看起来不对"，电话叫你看。

**用 Tinia SaaS（多组织协作场景）**：

1. 测试中心工程师在他自己的 Tinia 把看板 share 给你（生成 share 链接，内容快照固化、长期可访问）
2. 你点 share 链接 → 浏览器打开只读看板 / viewer
3. 你看了一下，跟测试工程师说"你这个数据采样率好像是 24k，我们之前都用 48k"
4. 测试工程师确认 → 重新采集

**时间**：5 分钟（之前要发邮件 + 等数据 + 用 HEAD 打开看 + 来回沟通几小时）

---

### 周五：周报 + 月度 review

**任务**：给老板做本周分析的周报 + 月度总结。

**用 Tinia**：

1. 跟 Claude Code 说"帮我整理本周 5 次分析的关键指标，写一份周报"
2. Claude Code 调用 `flow_run` 历史查询，拿到 5 个 GraphRun 的输出
3. 自动汇总成表格 + 关键趋势图
4. 写文字解读："本周 5 次测试中，A 样车在 12× 阶次能量比 B 样车高 3dB，可能是齿轮啮合刚度差异。建议下周做 modal 测试验证。"
5. 你审一遍 → 改几个判断 → 提交给老板

**时间**：30 分钟（之前 1.5-2 小时）

## 推荐 Edition + 报价方向

**推荐**：Pro 单 seat 订阅（**个人桌面**）。如果团队多人需要协作 → 升级到 **Server**（团队私有化 web）。

**报价方向**：

## 跟客户讲这个场景时

### 不要平铺直叙读 PPT

让客户讲他**自己的**一周，然后**对照场景**讲 Tinia 怎么解决他的痛点。

### 重点突出 2-3 个"我的天"时刻

- "你跟 AI 说一句话，AI 自动建项目写代码跑测试" → 让人感觉到代际差异
- "商店里订阅一个节点，立即就能用" → 跟"等下个版本"对比
- "share 链接给同事，他在浏览器里看到同样的可视化" → 跟"传文件"对比

### 给客户具体的 Demo 数据

不要用泛泛的"假数据"，提前问客户能否提供一段**他们真实工作的数据**做 demo —— 现场跑出来效果最震撼。
