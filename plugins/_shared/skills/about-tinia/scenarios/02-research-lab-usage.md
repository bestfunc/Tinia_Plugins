# 场景：高校 NVH 实验室 / 研究院

> 高校实验室的教学 + 科研双重场景，Tinia 怎么帮。这是节点生态最重要的"内容供给方"，销售要给教授讲明白长期价值。

---

## 客户画像

- **类型**：985/211 高校机械学院 / 振动学院 / 声学研究所
- **岗位**：教授 / 副教授 / 博士后
- **业务**：教学（带本 / 研学生）+ 科研（发论文 / 接横向项目）+ 培养下一代工程师
- **当前工具**：
  - 教学：MATLAB（学校买的）+ 板书 + PPT
  - 科研：自己写 Python / MATLAB 代码
  - 横向：偶尔借用其他单位 HEAD / Testlab
- **痛点**：
  - 学生写代码散乱，毕业带走，知识不沉淀
  - 给本科上课没有合适的"完整工具"，纯讲算法学生没感觉
  - 研究成果论文发了之后没人继续用 → 影响力低
  - 横向项目工具不专业，比不上有 HEAD 的大单位
  - 实验室自己想做"声学数据平台"但工程量太大

## 怎么用 Tinia

### 场景 A：教学（本科 / 研究生课程）

**之前**：

> 教授：今天讲 FFT，看这个公式 X(k) = ...
> 学生：（一脸懵）
> 教授：好，下课你们用 MATLAB 写一个，给我看图。
> 学生：（开始查 MATLAB 文档，一周后交作业一半人没出图）

**用 Tinia**：

1. 课前教授准备一个 Tinia 流程模板（含 `signal_generator` + `fft_spectrum` + `spectrum_viewer`）
2. 课上：
   - 投屏 Tinia 流程图
   - 修改 `signal_generator` 参数（频率 1000Hz → 2000Hz） → 实时看 `spectrum_viewer` 的频谱变化
   - 学生跟着自己电脑跑（Tinia Community 免费）
3. 作业：每人发一份课程数据，让学生**自己搭流程**完成"识别这段信号的主频" → 用 Tinia 评分

**收获**：

- 学生从"被动看公式"转向"主动玩流程"
- 教授不用教学生 MATLAB 语法，直接讲 NVH 概念
- 作业自动化批改更容易（流程 JSON 比代码好评）

### 场景 B：科研（研究生课题）

**之前**：

> 博士生：我写了个 Python 脚本算 Modulation Spectrum，但是数据预处理用 MATLAB，可视化用 matplotlib，散落在三个项目里。
> 教授：好乱。下次实验从头跑还能找到吗？
> 博士生：呃...

**用 Tinia**：

1. 博士生用 Tinia 搭流程：dataset → 预处理 → modulation_spectrum 节点（自己写的）→ viewer
2. 流程保存在 Tinia 项目里，跟数据源链接清晰
3. 论文 reviewer 问"能否复现"，博士生把流程 + 数据 export 出来给 reviewer
4. 毕业时把项目交给师弟师妹，整套流程能直接复用

**收获**：

- 实验流程沉淀，不丢失
- 知识传承（师兄毕业不带走全部代码）
- 论文复现门槛低，引用率潜在更高

### 场景 C：研究成果商业化（节点商店发布）

**这是 Tinia 给学术界最大的价值差异化**。

**之前**：

> 教授发了一篇心声 roughness 改进算法的论文，影响因子还行。但读论文的工程师没有现成工具能用 → 算法在仓库吃灰 → 引用数低 → 影响力有限

**用 Tinia**：

1. 教授把论文里的算法封装成 Tinia 节点 `dr-li/roughness-v2`
2. 发布到 Tinia 节点商店（公开）
3. 全行业 NVH 工程师能直接订阅 → 用
4. 用户评分 + 累积下载量成为该算法的影响力指标
5. 教授可以选择：
   - 免费发布：靠下载量获得学术影响力 + 行业认可
   - 付费发布：商店 30% 分成，获得被动收益

**长期价值**：

- 论文 → 节点 → 用户 → 反馈 → 改论文 → 良性循环
- 学生在节点商店有自己的发布记录 → 找工作简历加分
- 教授个人品牌建设：成为"行业标准算法的提供者"

### 场景 D：横向项目（给企业做咨询）

**之前**：

> 教授：我们实验室做这个 NVH 咨询，但用 HEAD 太贵 + 出报告不够专业
> 企业：你们工具不行，我们去找别人

**用 Tinia Pro**：

1. 实验室买一个 Pro seat（年订阅）
2. 接横向项目时用 Tinia 出专业报告（PDF 模板 + 公司 logo）
3. 项目里需要的专用算法 → 教授开发节点 + 留在实验室 org 私有池
4. 项目结束后流程沉淀，下次类似项目复用

**收获**：

- 工具专业度跟 HEAD 用户对等
- 流程模板复用提升交付效率
- 实验室积累"行业知识库"作为长期资产

## 教学场景的具体方案

### 课程方向 1：信号处理基础（本科）

- **课程节点**：signal_generator / fft_spectrum / spectrum_viewer / weighting_filter
- **作业模板**：流程文件 + 数据集，学生改参数 + 替换节点
- **课时安排**：每节课围绕 1-2 个节点讲

### 课程方向 2：声学测试方法（研究生）

- **节点**：dataset_node / level_meter / octave_analysis / roughness / loudness
- **作业**：完整的"测量某机械噪声 + 心声分析报告"
- **加分**：要求学生自己写一个 ParamsForm 改进现有节点

### 课程方向 3：声学算法实现（研究生 / 博士）

- **作业**：把论文里的算法实现为 Tinia 节点
- **评分**：节点能跑 + 跟参考实现对齐 + 可发布到商店
- **学生收获**：真实工程能力训练 + 节点商店发布记录

## 跟教授沟通的话术

### 不要

- ❌ 一上来推销 Pro
- ❌ 讲商业模式 / 产品分层 —— 教授对这个没兴趣
- ❌ 单纯讲"工具比 MATLAB 好"

### 应该

- ✅ 重点讲"教学场景的活泼度" —— 学生跟流程互动，比看公式有兴趣
- ✅ 重点讲"研究成果商业化路径" —— 老师论文成果通过商店流通
- ✅ 给免费课程模板 —— 让老师课堂用，自然就推开
- ✅ 邀请教授参加节点开发者计划 —— 给学术圈曝光

### 教授决策周期

- 通常学期开始前（2 月 / 8 月）是好时机
- 让教授先免费用 1 学期 → 满意后下学期推广
- 教授推荐效果最强：一个学生从教授课上接触到 Tinia → 毕业后到企业当工程师 → 反向推销
