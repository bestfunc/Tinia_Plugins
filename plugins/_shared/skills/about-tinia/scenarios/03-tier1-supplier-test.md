# 场景：Tier1 供应商 NVH 测试部门

> Tier1 测试部门是 Tinia Pro 的核心目标客户之一。给销售完整描述他们的业务场景 + 报告交付链路 + Tinia 怎么帮。

---

## 客户画像

- **公司类型**：汽车 Tier1 供应商（动力总成、底盘、座椅、内饰、电子等子系统）
- **部门**：测试中心 NVH 测试室
- **岗位**：测试工程师 + 主管 + 部门经理
- **团队规模**：通常 5-30 人
- **业务模式**：
  - 接主机厂订单 → 出 NVH 测试报告
  - 项目周期 1-3 个月
  - 同时服务 5-20 家主机厂
- **当前工具**：HEAD ArtemiS（核心）+ MATLAB（专项） + 自家 Excel 模板
- **痛点**：
  - 主机厂模板各家不一样，维护 N 套报告模板很乱
  - 报告交付周期短（有时几天内）
  - 主机厂线上问"为什么这个指标偏高" → 要回头复现分析（耗时）
  - 流程不沉淀，老工程师离职新人重做
  - HEAD seat 不够，工程师排队等

---

## 业务流程速写

### 典型一个项目（之前）

```
主机厂下单
    ↓
样件入库 + 测试计划
    ↓
台架 / 转鼓测试（1-3 天）→ 产生原始数据
    ↓
工程师分析（用 HEAD + MATLAB） → 1-3 天
    ↓
按主机厂模板出报告（Word + 图表）→ 0.5-1 天
    ↓
内部 review + 修改
    ↓
交付主机厂
    ↓
主机厂反问"为什么..."→ 回头复现 → 半天-1 天
```

**痛点**：

- 模板维护：N 个主机厂 = N 套报告模板，工程师怕用错
- 复现：旧项目 6 个月后要复现，老工程师记不清当时怎么搭的分析
- 知识沉淀：离职带走经验
- 多项目并发：5-10 个项目同时跑，工具切换累

## 用 Tinia Server（团队私有化）后

### 1. 流程模板库（按主机厂分类）

每个主机厂一个流程模板：

```
组织：testlab_acme（公司 Tinia 组织）
├── 流程模板/
│   ├── 大众 NVH 标准报告
│   ├── 比亚迪 NVH 标准报告
│   ├── 蔚来 NVH 标准报告
│   └── ... （20 个主机厂）
├── 报告模板/
│   ├── 大众_PDF模板
│   ├── 比亚迪_PDF模板
│   └── ...
└── 共享凭据 / 数据源配置
```

工程师接新项目：

1. 选对应主机厂模板 → 一键 fork 流程
2. 替换数据源 → 跑
3. 用对应报告模板导出
4. **不会用错**，因为流程跟报告模板绑定

### 2. 一份报告 = 一个 GraphRun 快照

每次出报告时，Tinia 自动保存：

- 流程定义快照（确切的节点 + 参数）
- 数据源引用
- GraphRun 状态（每个节点的 outputs handle）
- 时间戳 + 操作人

主机厂半年后问"为什么这个指标偏高"：

1. 工程师从历史报告找到对应 GraphRun ID
2. 一键复现：Tinia 拉起当时的快照
3. 工程师在 Viewer 里检查具体节点的 outputs
4. 5 分钟内能回答（之前要重新搭分析半天到一天）

### 3. AI 写报告解读

跑完流程后跟 Claude Code 说：

> "帮我写这份报告的'分析总结'部分，重点说为什么 25 阶次能量高"

Claude Code 自动：

- 读 GraphRun 的所有节点输出
- 对照标准参考数据（比如 ISO 标准）
- 写一段解读："25 阶次 (28-30Hz 段) 振动能量较参考样件高 4dB，可能由 X 引起..."
- 工程师审 + 改 → 加进报告

→ 报告"分析总结"部分从写 1 小时 → 改 10 分钟

### 4. 团队共享 + 权限分级

- **测试工程师**：跑流程 / 出报告（流程模板只读）
- **资深工程师**：能改流程模板 / 创建新模板
- **部门主管**：能看全部项目 / 审批模板变更
- **公司管理员**：管 Org / Seat / 凭据

不需要每个人都装 HEAD（昂贵 seat），需要分析的人有 Pro seat 即可。

### 5. 新算法上线快

主机厂某天说"这个项目要做'电机齿轮啸叫识别'，我们标准里有"：

**之前**：HEAD 不带 → 等下个版本 → 自己写 MATLAB → 写完几天

**用 Tinia**：

- 商店搜 → 有现成节点 → 订阅 → 5 分钟用上
- 商店没现成 → AI + 工程师自研 → 2-3 小时 → 加到流程
- 公司私有发布 → 同事下次也能用

## 量化收益（销售可引用）

> 以一个 10 人 NVH 测试团队、月接 30 个项目为基准估算（实际数字按客户具体情况调整）：

| 维度 | 之前 | Tinia Server（团队私有化） | 节省 |
|---|---|---|---|
| 单项目报告交付时间 | 3-5 天 | 1-2 天 | ~60% |
| 模板维护成本 | 高（容易用错）| 模板库系统化 | 减少出错 |
| 旧项目复现 | 半天 - 1 天 | 5-30 分钟 | ~95% |
| 新算法上线 | 等版本 + 自研 | 商店订阅或 AI 自研 | 数量级 |
| HEAD seat 排队 | 工程师等 | Pro seat 按团队铺 | 不再排队 |
| 月度报告数量 | 30 个 | 40-60 个 | ~50% 产能提升 |

**全年收益估算**：

- 节省的工时换算成可接更多项目 → 营收提升
- 报告质量稳定（模板化）→ 主机厂满意度提升 → 续约率提升
- 新人培养周期从 6 个月 → 1-2 个月 → 招聘灵活

## 销售切入路径

### 接触方式

- **测试经理 / 主管**：决策者，跟他讲"团队效率 + 标准化 + ROI"
- **测试工程师**：实际用户，让他们试 → 形成正面反馈推动决策者

### 试点项目（关键）

不要一上来卖 N seat 包年，**从试点开始**：

1. 给 1-2 个 Pro seat 免费试用 3 个月
2. 让团队选 1-2 个真实项目用 Tinia 跑完整流程
3. 试用结束时对比 vs 用 HEAD 的同类项目工时
4. 数据说话 → 决策者好做采购预算

### 异议处理

**Q：我们已经投了 HEAD，再买 Tinia 是不是浪费？**

A：不是替换关系。Tinia 跑日常项目（80%），HEAD 留给少数需要深算法（EMA / TPA）的场景。总成本可能更低 + 团队产能更高。

**Q：报告主机厂会接受吗？**

A：报告是 PDF / Word 文件，跟主机厂工具无关。我们提供 4 个内置模板 + 完全定制，主机厂只看报告内容不看工具。

**Q：5 年后 Tinia 还在吗？**

A：流程 JSON + 数据是开放标准，Tinia 没了能用别的工具读。核心 engine 是 Apache-2.0 开源。

**Q：我们 IT 不让用 SaaS，必须本地**

A：提供公司私有化部署方案，数据 100% 在你们内网。

```

   ↓

   ↓
```

- 决策时（步骤 5-7）：销售跟经理 / 采购对接，准备方案 + 报价
