## 五条不可复制的差异化

> 前三条（MCP / DAG / 商店）是结构性差异；后两条（SDK 通路、常驻执行 + 看板）是 2026 年中新增的主线卖点，进一步拉开"平台 vs 单机工具"的代差。

### 1. MCP-native 协作 ✅

**为什么对手追不上**：

- HEAD / Testlab 基于桌面单机架构演进多年，进程模型 + UI 架构非为"外部 AI 调用"设计
- 要做 MCP 接入需要重写大量基础设施（HTTP server、auth、事件总线）
- 现有 SDK 只是给"人写代码"用的，不是"AI 自动调用"的
- 即使他们意识到要做，也要数年重构

**Tinia 的实现**：

- 主仓内置 MCP server（JSON-RPC 2.0 over HTTP），AI 客户端直连
- OAuth 2.1 + PKCE + 动态客户端注册（DCR）让 AI 客户端一键授权；装 `tinia-desktop` 插件后本机可免 OAuth 直连
- 70+ 个 MCP 工具，覆盖 8 个模块（dev / nodes / graphs / data / data_write / templates / assistant / plugins）：项目 CRUD / 文件读写 / 节点脚手架 / 编译 / 跑流程 / 发布 / SDK 管理 / 通道模板等
- 全局 AI 活动面板（跟随 / 旁观双模式）+ 流程编辑器视觉联动；AI 一次操作可完成多步（加节点 + 连线 + 改参 + 布局），失败自动回滚；插件审批由用户手动确认
- 全部操作进审计日志（`mcp_audit_logs`）
- Claude Code / Codex / Qwen CLI 装上 `Tinia_Plugins` 中的 plugin 即用

详见 `11-mcp-ai-integration.md`。

### 2. 节点 DAG + AI 编排（不是脚本，是声明式图）✅

**为什么对手追不上**：

- 传统工具是"菜单驱动 + 模块化处理"，工程师在菜单里一步步点
- HEAD ArtemiS 16 才加 Automation Project（脚本化向导），本质仍是命令式
- Siemens Process Designer 也是相同形态
- 改成 DAG 需要重做核心数据流模型，不是 UI 改改的事

**Tinia 的实现**：

- 流程是有向无环图（DAG），节点为顶点，数据流向为边
- 执行引擎按拓扑序调度，节点完成后自动把 outputs 通过 blob handle 传给下游
- 这是**声明式**而非**命令式** —— AI 能直接读懂、改、新建
- 工程师说"我要看这段信号的频谱在转速 1000-3000 RPM 段的演化"，AI 能自动搭 DAG

### 3. 开放节点商店（tinia-store）✅

**为什么对手追不上**：

- HEAD / Testlab 的商业模式是"卖大厂自己的软件"，开放商店会侵蚀模块收入
- Ansys / Abaqus 有 user subroutine（自定义代码扩展）但没有"商店"概念
- 真正的"App Store"需要支付 / 分成 / 审批 / 推荐算法的完整基础设施

**Tinia 的实现**：

- `Tinia_Store` 独立服务，独立可部署
- 节点发布审批 + 用户订阅 + 商业节点收费 + 30% 平台分成
- 公开（所有人可订阅）/ 私有组织池（仅组织内可见）两种发布范围
- 在线发布订阅已可用（@handle 命名空间隔离），对外生态持续推进

### 4. Python SDK 通路：外部程序直接调用平台算力 ✅

**为什么对手追不上**：

- 传统大厂 SDK 是"给人写代码"的库，要自己管凭据、地址、数据序列化，且算法版本绑死在客户端
- Tinia 的 SDK 是**通路而非第二引擎** —— 外部 Python 程序传数据、拿结果，算法仍在平台执行；平台改了参数，调用方零改动自动生效

**Tinia 的实现**：

- 超管「SDK 管理」输入名称即生成可下载 SDK 包，**凭据 + 服务器地址已内置，零配置**（鉴权走 license，不是手填 api_key）
- 三种调用方式：① 直接传节点类型 + 参数；② 用节点表单「复制参数」拿到的参数串；③ 引用平台流程里调好的节点（平台改参自动生效）；整条流程也能整体调用（API 输入 / API 输出 节点）
- 传数据便利：直接传文件路径（wav/csv/npz/tdms）或内存数组自动上传；单输入节点连端口名都不用写
- **同机调用自动走本地直连（Unix domain socket）+ 路径直传**，大文件显著更快
- **流式会话 / 实时数据流**：持续往流程推数据、实时取回计算结果，跳过缓存走内存中转，适合在线 / 边采边算场景（声级计 / 频谱 / 倍频程节点支持跨窗无缝逐帧）
- 超管「SDK 调用分析」可查看每个 SDK 的调用量、成功率、耗时、Top 节点、最近失败
- 官方 40 个节点已全部补齐「SDK 说明」示例代码

> 一句话卖点："把你们调好的分析变成一个内网 API，产线 / 测试程序一行 `connect()` 就能用，算法升级不用动调用方。"

### 5. 常驻执行加速 + 看板驾驶舱 ✅

**常驻执行池（Resident Execution Pool）**：

- 分析节点进程可常驻待命（只加载一次），SDK 高频 / 实时调用直接复用热进程，省掉每次启动进程 + 加载库的固定开销（约 530ms → 纯计算）
- 超管「常驻执行」页可查看运行状态、调进程上限 / 空闲回收、勾选需预热的节点（预热白名单）
- 配合节点输出缓存（按输入指纹自动命中），高频重复分析近乎瞬时返回

**看板 Dashboard**：

- 从"组合视图的报告"成长为可整屏排版、可分享、支持富媒体的驾驶舱
- 组件类型：视图 / 章节标题 / 富文本（含插图）/ Item 列表 / 维度筛选器 / 单图多图切换 / **HTML 组件** / **视频组件**
- 批量编辑（多选同类组件统一改属性 / 套用显示配置）、整屏排版（缩到一屏拖动重排）
- 分享链接固化内容快照，长期可访问、不随运行记录清理失效
- 大数据看板先显示框架再按需加载，首屏更快

> 传统大厂的"报告导出"是一份静态文档；Tinia 看板是**可交互、可分享、能嵌 HTML/视频的在线驾驶舱**，且数据冻结快照保证长期可复现。

## 对手强项（Tinia 短期不追的）

要诚实告诉客户 Tinia 现在**还做不到**或**短期不做**的事：

| 对手强项 | Tinia 现状 / 计划 | 给客户的话术 |

| **EMA / 模态分析** | ❌ 暂不做，路线图评估 | "重型功能，我们暂不做。如果是模态分析为主，HEAD/Testlab 更合适。但 90% NVH 工程师不每天用 EMA" |
| **TPA / 传递路径分析** | ❌ 同上 | 同上 |

## 销售场景：客户对比时怎么应答

### 场景 A：客户说"你们功能没有 HEAD 全"

**❌ 错答**："我们正在追，今年就能有 XX"
**✅ 正答**：

> "您说得对，HEAD 30 年累积的算法清单很全。但请问您日常用到的是哪 10-20 个核心算法？这些 Tinia 都有。HEAD 那些深功能（EMA / TPA / 全套建筑声学），90% 工程师 99% 时间用不到。
>
> Tinia 的差异化不是'算法多少'，是'**工作方式**'：节点 DAG + AI 编排 + 节点商店即时更新。我们一份月度报告，HEAD 用户 2 天，Tinia 用户 2 小时。"

### 场景 B：客户说"你们便宜是因为功能少"

**❌ 错答**："不是不是我们也有 XX 功能"
**✅ 正答**：

> "我们便宜不是因为功能少，是因为架构代际不同。
>
> HEAD 基于桌面单机架构的成熟商业软件 → 边际成本高 → 单 seat 必须贵
> Tinia 云原生 + 订阅 + AI 增效 → 边际成本接近零 → 我们能定低价
>
> 我们功能虽不及 HEAD 累积全，但**该有的核心都有 + AI 工程师助手 + SDK 把算法变内网 API + 常驻执行加速，这些是 HEAD 短期不会有的**。"

### 场景 C：客户说"我们这是大企业，工具要稳定，不敢用新的"

**❌ 错答**："我们也很稳定您放心"
**✅ 正答**：

> "理解您的顾虑。这是 Tinia 的**典型客户决策路径**：
>
> 1. 先试用 Community 或 Pro 试用 3 个月，让 1-2 个工程师在非关键项目里用
> 2. 出了 2-3 个真实案例，证明 Tinia 能做 + 工程师真喜欢
> 3. 再在团队层面铺开
>
> 这是低风险高回报的路径。HEAD 不会从您预算里消失，Tinia 是**新增**而非**替代**。"

### 场景 D：客户问"5 年后你们还在吗？怎么避免被锁死"

**❌ 错答**："放心我们融了很多钱"
**✅ 正答**：

> "三层保障：
>
> 1. **流程 JSON 开放**：您的流程定义就是个 JSON 文件，标准化 schema，无论 Tinia 在不在都能解析
> 2. **节点代码可控**：商业节点您能看到接口、签合同保留源码托管；自研节点完全在您手里
> 3. **数据 / 算法可带走**：私有化 / 桌面单机部署，数据和已调好的分析都在您的环境里；SDK 调用是标准 HTTP/license，不绑死任何客户端
>
> 我们认为最大的护城河不是 lock-in，是产品好让您不想走。"

## 不直接对比的关键："投资人 vs 客户"叙事

**对客户**：讲"工作方式升级 + 工具效率提升 + 节点商店"
**对投资人**：讲"AI-native 工程操作系统 + 节点商店生态 + 长期取代传统工具"

两边叙事不冲突，但**侧重不同**：

- 客户最关心当下我能省多少时间 / 钱
- 投资人最关心 5 年后 TAM 有多大 / 护城河有多深

不要给客户讲"我们要取代 HEAD"——客户会怕"你倒了我没人用"，**讲"我们补充 HEAD" + "AI 工程师是新的工具范式"**。
