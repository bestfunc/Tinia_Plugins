# 定价与商业模式

> Tinia 的商业 SKU（Community / Pro / Server / SaaS / Production）分别怎么收钱，商店 30% 分成怎么运作，长期商业护城河逻辑。**具体价格数字不在本 skill 暴露**，由销售按客户情况报价。
>
> 口径提示：部署层只有 desktop / server / saas 三种形态；Community 与 Pro 都是桌面形态的不同授权档（Pro 靠激活解锁）。**Community / Pro / Server / SaaS 已交付**；**Production（产线版）为路线图/规划中**。

## 收入来源

```
┌────────────────────────────────────────────────────────────────┐
│  Tinia 总收入                                                  │
├────────────────────────────────────────────────────────────────┤
│                                                                │
│  1. Pro 软件许可（个人，订阅 / 买断）  ← 已交付，当前收入主体        │
│  2. Server 软件许可（团队，私有化）    ← 已交付，当前收入主体        │
│  3. SaaS 订阅（多组织云端）            ← 已交付，按 seat 订阅                   │
│  4. Production 项目交付                ← 路线图（规划中）                │
│  5. 商店分成（商业节点 30%）            ← 对外开放后（规划中）          │
│  6. 企业服务（培训 / 定制开发 / 实施） ← 持续                     │
│                                                                │
└────────────────────────────────────────────────────────────────┘
```

### 1. Pro 软件许可（个人 SKU，核心收入之一）

**适合谁**：个人 NVH 工程师 / 独立顾问 / 自由职业。

**两种定价模式**：

| 模式 | 适合谁 | 优势 |
|---|---|---|
| **按 seat 订阅**（推荐）| 长期个人用户 | 现金流均匀；订阅期内节点商店全量更新 + 客服 + 升级 |
| **永久买断 + 维护费** | 一次性预算审批的客户 / 中国大型国企采购流程 | 一次付清；1 年免费更新 + 之后按年付维护费 |

**Seat 模型**：

- 1 seat = 1 个用户被授权使用 Pro 功能
- 跨多设备：单 seat 默认绑 3 台设备（个人 PC + 笔记本 + 公司机）
- 学生 / 教育许可：单独折扣计划

**Pro 试用**：

- 新用户可以申请 3 个 seat × 3 个月免费试用
- 试用到期自动降级到 Community，保留全部数据
- 不要"自动续费陷阱"，到期前主动提醒

### 2. Server 软件许可（团队 SKU，核心收入之一）

**适合谁**：公司 NVH 部门 / Tier1 测试团队 / 检测中心 / 合资 OEM / 国企。

**两种定价模式**：

| 模式 | 说明 |
|---|---|
| **按团队 seat 订阅** | 团队 N seat，组织管理员分配给 N 个具体用户；订阅期内享更新 + 优先支持 + 实施服务 |
| **永久买断 + 维护费** | 一次付清 + 后续年付维护费；适合大企业一次性预算 |

**Server 套餐通常含**：

- 团队 seat 数量（5/10/20/30/50/100+ 阶梯）
- 私有化部署服务（含 1-2 天远程协助）
- 优先支持 SLA（典型响应 12 小时内）
- 用户培训（远程 1-2 天免费）

**离职 / 转岗**：

- Seat 可由组织管理员回收 + 重新分配
- 用户数据 / 流程留在组织内不丢失

**Server 试用**：

- 提供 30 天 PoC 试用（含小规模部署支持），让客户先验证再采购

### 3. SaaS 订阅（已交付）

云端多组织版本，按 seat 月付 / 年付订阅。多租户已全面组织化：一人可属多组织、组织间数据严格隔离、顶部组织切换器、权限按组织独立配置。适合不愿自建服务器、又要团队协作的客户。

### 4. Production 项目交付（路线图 / 规划中）

**计费模式**：项目制（含咨询服务、定制集成、培训）

**典型项目类型**：

- 风电场远程 CMS：N 个机组 × N 个传感器，云端 + 边缘混合
- 工业泵厂 PdM：N 条产线，跟 MES 集成
- 整车厂下线检测：替代 NG 检测线，加 NVH 在线监测能力

**Production 跟现有形态的关系**：

- 同一份执行引擎（执行只发生在 tinia-server 进程内），同一个节点生态
- 现有 Server + SDK 已能做产线 PoC（SDK 流式会话 + 常驻执行加速）；Production 是把这些能力产线化封装的路线图项
- 现有客户的"零迁移"升级路径
- Production 通常含若干 seat 给现场调参用

> 注：在 Production 落地前，"实时流处理 / 边采边算 / 把分析变内网 API"这些产线核心诉求，已可用 **SDK 流式会话 + 常驻执行池** 现成实现，详见 `06-competitive-landscape.md`。

### 5. 商店分成（对外开放后 / 规划中）

**模式**：30% 平台分成（参照 Apple App Store / Steam 路径）

**流程**：

1. 开发者写节点 → 在 Tinia_Store 上架
2. 设置价格（一次性买断 / 月付订阅）
3. 用户从主仓 UI 浏览 → 订阅 → 自动安装到自家 Tinia
4. 收益按月结算：开发者拿 70%，平台拿 30%

**节点类型**：

- **免费节点**：所有人可用，开发者无收益，但累积下载量是简历加分
- **商业节点**：付费才能装，开发者按订阅 / 买断收益
- **私有组织节点**：仅某 Org 内可用，组织内开发的工具，不进公开市场

**质量保障**：

- 商店审批：算法正确性 + 性能 + 安全（不调外部 API 泄露数据）
- 用户评分 + 评论
- 下载量 / 收益排行榜推动好节点冒头

详见 `12-node-ecosystem.md`。

### 6. 企业服务

- **培训**：现场培训、视频教程定制、认证课程
- **定制节点开发**：客户提需求，我们做节点（属于客户独占或上架商店）
- **集成咨询**：跟客户现有数据流 / MES / 实验设备的集成
- **支持 SLA**：Server 套餐含优先支持，企业 SLA 单独签

## 三层定价的内在逻辑

### 为什么 Community 免费

- **建立生态正循环**：研究者 → 发布算法到商店 → Pro 用户订阅 → 反哺 Pro 价值
- **反向培养未来 Pro 用户**：学生用 → 工作后向公司推荐
- **传统大厂不敢做**：HEAD/Testlab 的核心客户是大企业，免费版会侵蚀付费版收入
- **Tinia 起步无包袱**：没有存量大客户被侵蚀

### 为什么 Pro 价格能比 HEAD / Testlab 低

| 因素 | 传统大厂 | Tinia Pro |
|---|---|---|
| 软件部署 | C++ 单机软件，每客户独立工程 | 云原生，多客户共享底座 |
| 更新机制 | 年度大版本，重型工程 | 节点商店即时更新，小步快跑 |
| 客服模式 | 现场培训 + 高级工程师电话 | AI 助手 + 文档 + 异步邮件 |
| 销售模式 | 重型直销，长决策周期 | Pro 试用直接触达，缩短销售周期 |

→ **单 seat 边际成本接近零** → 能定低价 → 抢市场

### 为什么 Production 是项目制

- 在线监测涉及硬件集成、MES 对接、定制开发，无法标品化
- 客户预算来自"工厂设备改造"，按项目走
- 项目价值高，毛利率比 Pro 订阅高

### 商店分成为什么是 30%

- 行业标准（Apple / Steam / Microsoft Store 都是 30%）
- 留给开发者 70% 足够激励高质量贡献
- 商店运营 / 审批 / 推广成本占 30% 不亏

## 商业护城河

**Tinia 的护城河有 3 层**（从浅到深）：

### Layer 1：节点生态（开放商店）

- 一旦商店生态形成，竞争对手要复制需要：
  - 商店基础设施（支付 / 审批 / 推荐）
  - 几百个高质量节点
  - 几千个注册开发者
- 这是几年时间窗口

### Layer 2：MCP-native + SDK 通路（AI 工作方式 + 集成锁定）

- 工程师习惯了"AI 帮我搭流程"以后，回不去手工编排
- 一旦客户把产线 / 测试 / 自动化系统通过 SDK 接到平台调用算力，分析就成了他们生产链路的一环——切换成本远高于换一个单机软件
- 这种工作方式 + 集成锁定比"功能锁定"更深
- 对手追上 MCP + 零配置 SDK 通路需要重写架构（数年）

### Layer 3：数据 + 模型沉淀（Production 阶段）

- Production 客户的工厂数据沉淀 → 行业模型库
- 模型库越积累越准、越准 → 客户越离不开
- 这是 SmartQuality 已经走通的路径，Tinia Production（路线图）复用

**短期**：靠 Pro / Server / SaaS 现金流回血；SDK + 常驻执行打开"产线 PoC"窗口
**中期**：节点商店生态打开 + Production 第一批客户
**长期**：行业模型库 + 全行业默认工具

## 销售常见问题

### "为什么不开源全部？"

- 平台核心（执行引擎、多租户、商店、AI MCP 集成）保留闭源 —— 这是商业模式核心
- **节点 SDK（tinia_runtime / tinia_audio / tinia_features 等）随主程序内嵌可见**，节点开发者能拿到完整契约与类型提示（`tinia sdk install` 本地拷一份做 IDE 提示）
- 客户侧的可带走保障靠"流程 JSON 开放 + 数据可带走 + SDK 走标准 HTTP/license"，不依赖 engine 开源
- 节点开发者保护：详见 `docs/plugin-protection-design.md`

> 历史说明：早期路线图曾设想把 engine（`Tinia_Engine`）、runtime（`Tinia_Runtime`）抽成独立开源仓库，该方案现已归档——双引擎必然版本漂移，收益被"桌面单二进制 + headless + SDK 通路"覆盖；节点 SDK 唯一源已并入主仓。

### "竞品免费推广怎么办？"

- HEAD / Testlab 商业模式决定他们不会免费推广（核心客户付费保护）
- 如果某天他们出免费版，意味着 Tinia 已经威胁到他们了 —— 反而是好消息
- 防御：靠 MCP-native + 商店生态做工作方式锁定，不靠价格战

### "5 年内能盈利吗？"

- 当前已小规模付费（Pro / Server / SaaS 均已交付），验证产品市场契合度（PMF）
- 节点商店开放 + Production 项目入账后进入增长期（均为路线图项）
- 公司层面 Bestfunc 已有现金流业务（SmartQuality、Argus），Tinia 不需要立刻盈利

### "渠道商怎么分？"

- 目前直销为主
- 中期考虑授权代理（NVH 行业咨询公司 / 区域代理）
- 渠道分成模型按行业惯例，由 BD 谈判

## 给销售的报价心法

### 不要先报价

让客户讲清场景（N 个工程师、是否要私有化、是否要培训）→ 你才能报合适的方案。

### 给"省钱叙事"+"提效叙事"组合

- **省钱叙事**：跟 HEAD/Testlab 比，单 seat 价格低 → 财务好审批
- **提效叙事**：AI 助手让工程师产出翻倍 → 业务好认同
- 缺一不可 —— 只讲省钱客户觉得"便宜没好货"，只讲提效客户没办法走预算流程

### 灵活：年付 / 月付 / 一次性

- 创业公司 / 个人偏向月付（现金流）
- 国企 / 大企业偏向年付或一次性（预算审批）
- 不要硬塞模式，灵活报

### 试用是销售关键

- Pro 试用 3 个 seat × 3 个月，无信用卡，无续费陷阱
- 试用期内的客户成功是最重要的销售活动
- 试用期到期前 2 周主动联系，转化率最高
